> 4K 的**单价**比 1080p 低，但 4K 生成的 token 量大得多，总价更高。别被单价误导，要算总量。

### 3.2 成本公式（核心）

```
视频价格 = token 单价 × token 用量

token 用量 = (输入视频时长 + 输出视频时长) × 输出宽 × 输出高 × 输出帧率 / 1024
```

- **Draft 草样片模式**折算系数（seedance 1.5-pro）：无声 ×0.7，有声 ×0.6；其他模型暂不支持。
- 因审核等原因生成失败的，**不计费**。
- 输入含视频时，seedance-2.0 / 2.0-fast 有**最低 token 用量限制**，低于则按最低计。
- 准确用量以 API 返回的 `usage.completion_tokens` 为准。

## 9. 能力与限流 ✅

> 来源：火山方舟 **模型列表** 页 https://docs.volcengine.com/docs/82379/1330310?lang=zh
> 页面更新时间 2026.07.14 23:12:52 ｜ 归档 2026.07.20
> 这一节和前面的价格表是两个维度：价格决定单次成本，**限流决定你一天能跑多少**。

### 9.1 上下文与限流对照 ← 本节核心

| 模型 | 上下文窗口 | 最大输入 | 最大回答 | 最大思维链 | 最大 RPM | 最大 TPM |
|---|---|---|---|---|---|---|
| **doubao-seed-evolving** | **1024k** | **1024k** | 256k（默认 4k） | 256k | 500 | 1,000,000 |
| doubao-seed-2-1-pro-260628 | 256k | 256k | 256k（默认 4k） | 256k | 500 | 1,000,000 |
| doubao-seed-2-1-turbo-260628 | 256k | 256k | 256k（默认 4k） | 256k | 500 | 1,000,000 |
| doubao-seed-2-0-lite-260428 | 256k | 224k | 128k（默认 4k） | 128k | **30,000** | **5,000,000** |
| doubao-seed-2-0-mini-260428 | 256k | 224k | 128k（默认 4k） | 128k | **30,000** | **5,000,000** |
| doubao-seed-2-0-pro-260215 | 256k | 224k | 128k | 128k | 30,000 | 5,000,000 |
| doubao-seed-character-260628 | 128k | 96k | 32k | 128k | 30,000 | 5,000,000 |

**三条结论：**

1. **RPM 差 60 倍、TPM 差 5 倍。** 旗舰三兄弟（evolving / 2.1-pro / 2.1-turbo）都是 RPM 500；往期档一律 RPM 30,000。**做批量任务时旗舰的瓶颈不是钱，是队列。** 每分钟 500 次请求 = 每秒 8 次，跑并发管线很快就撞墙。
2. **`evolving` 的真差异化是 1024k，不是模型强度。** 全线唯一超过 256k 的。要一次性塞进一整份长文档 / 一整个知识库再推理，只有它。这也解释了它为什么和 2.1-pro 同价（6.00/30.00）却单独列一档。
3. **限流是「非刚性保障，受平台负载/调用方式影响」**——官方原话。写在往期模型表头上。**别把 RPM 30,000 当 SLA 写进方案。**

### 9.2 「最大回答默认 4k」的省钱点

所有模型的 `max_tokens` 默认值都是 **4k**。而 `doubao-seed-1.8` / `gm-4.7` 是按**目标输出长度**分档计价的（见 1.1 节），分界线在 **2k**。

> **默认配置就已经落在贵的那一档。显式把 `max_tokens` 设到 2000 以内，输出费直接降 4 倍。**

### 9.5 工具调用能力（哪些模型能挂什么）

维度：函数调用 / 知识库 / MCP / 联网内容插件 / 图像处理 / 豆包助手。

- **全能**：`evolving`、`2.1-pro`、`2.1-turbo`、`2-0` 全系、`glm-5-2`、`deepseek-v4-pro/flash`——六项全支持，且 Responses API 与 Chat API 都可用。
- **只有函数调用**：`doubao-seed-character` 系列——其余五项全是「—」。做角色扮演类应用要注意，**它挂不了知识库和 MCP**。
- **只支持 Chat API**：`doubao-1-5` 全系（且即将下线）。

### 9.6 上下文缓存

- **推荐档**（evolving / 2.1-pro / 2.1-turbo）：隐式缓存走 Responses API + Chat API；显式缓存支持**前缀缓存**和 **Session 缓存**。
- **往期 1.5 档**：隐式只走 Batch API，显式走 Context API，Session 缓存是 `rolling_tokens` 模式。

> 缓存命中价是输入价的 **1/5**（2.1-pro：1.20 vs 6.00）。**长 system prompt / 固定知识库前缀，用显式前缀缓存能直接省 80% 输入费。** 这是本文里第二个立刻能省钱的开关（第一个是 9.2 的 max_tokens）。
